# Dispatch HQ — Development Guide

## Prerequisites

- **Node.js** (recent LTS; the lockfile is generated by pnpm 9.15)
- **pnpm** 9.x — `corepack enable` or `npm i -g pnpm@9`
- **PostgreSQL + Redis** for the backend — the quickest path is `docker compose up -d` from `infra/docker/` (matches the default `DATABASE_URL` / `REDIS_URL` in `servers/game-server/src/config.ts`)

## Setup & run

```bash
pnpm install
pnpm dev        # web (:3000) + game-server (:3001) + game-engine (watch)
```

Open http://localhost:3000. The Vite dev server proxies `/api` and `/ws` to the
**live production server** by default (`apps/web/vite.config.ts`), so the game
works even with no local backend. To run fully local, start the backend first —
the client will use `http://localhost:3001` when it is reachable.

### Local DB

```bash
cd infra/docker && docker compose up -d     # postgres + redis
cd ../../servers/game-server
pnpm db:push                                # apply the Drizzle schema
curl -X POST http://localhost:3001/api/seed # idempotent seed (demo player, achievements, DHQ-LAUNCH promo)
```

## Conventions

- **UI:** Tailwind dark-first (`bg-gray-950`, `text-white`), lucide-react icons, framer-motion for animation (gate heavy motion behind `prefers-reduced-motion`), MapLibre GL for the map.
- **Missions always go through `apps/web/src/lib/spawn.ts` `buildMission()`** — never construct mission objects ad hoc. New templates are data in `packages/shared/src/constants/missions.ts` (+ a test in `missions.test.ts`).
- **Shared constants/types live in `packages/shared/src`** — keep the client and server on one source of truth. Progression numbers (XP curve, level bonuses) are in `constants/economy.ts` and must stay in lockstep (index-parity test enforces it).
- **Server:** Hono middleware order matters — auth before routes (see the runbook lesson in `plans/RELEASES.md`). Every new player-referencing table must be added to `UPGRADE_REKEY` in `routes/auth.ts` (the upgrade test guards it).
- **Security-sensitive writes** (auth, promo redeem, chat, bug reports) are rate-limited per IP in `serve-combined.ts`; keep new public endpoints on the same pattern.
- **Testing:** vitest per package. Pure logic → unit tests; component tests for key panels (e.g. `AdminPanel.test.tsx`). Test files live next to the code (`*.test.ts`).
- **Vitest 4 note:** `**/dist/**` is NOT in the default test excludes anymore — every package's `vitest.config.ts` adds it back so compiled test copies don't double-run.

## Release checklist

1. Typecheck: `pnpm --filter @dispatch-hq/web exec tsc --noEmit` + same for `game-server`; `pnpm build`.
2. Full test pass per package.
3. Add a `RELEASE_NOTES` entry (`apps/web/src/data/releaseNotes.ts`) and bump the version in the **three** places: `serve-combined.ts`, `index.ts`, `releaseNotes.ts`.
4. Bump the service-worker cache (`apps/web/public/service-worker.js`, `CACHE_NAME`) so returning players pull the new bundle (the deploy script verifies this).
5. Deploy with `scripts/deploy.sh <VERSION> <files...>` following the `plans/RELEASES.md` runbook end-to-end (backup → byte-exact transfer → build → restart → verify `/health`).

## Troubleshooting

- **`/health` returns 503 “Database connection failed”** — Postgres isn't running (`docker compose up -d`).
- **Auth 401s after a restart** — `JWT_SECRET` isn't pinned in the service env; tokens minted with a different secret orphan sessions. Pin it (see `plans/RELEASES.md`).
- **Test failures mentioning PORT** — the config tests snapshot/restore `PORT`/`HOST`, so any shell env is fine; stale `dist/` copies of tests are excluded by the vitest configs.
- **CORS errors from a custom origin** — extend `CORS_ORIGIN` (comma-separated) in the service env; the allowlist is in `servers/game-server/src/config.ts`.

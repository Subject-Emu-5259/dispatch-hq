## Decisions

1. **Puppeteer over Playwright for the e2e.** The v0.22.0 plan text said
   "Playwright," but Puppeteer is already a project dependency driving the
   trailer/browser-verification tooling. Adding Playwright is churn for the
   same job. *Override here if Playwright is actually wanted.*
2. **Jail capacity gets a real gate, not a display cap.** The v0.20.1 drop was
   exactly right: no fake caps. Since a jail gate doesn't exist yet, Slice 2
   adds a minimal one (auto-`transferred` on overflow) so the perk is
   mechanical. This is the only scope expansion vs. the v0.22.0 text.
3. **Perk magnitude is flat per station** (+8 jail slots / +5 beds), matching
   the existing `StationPerk.value` model (one perk = one effect), not
   "per level." Stackable across stations, consistent with the reward-perk cap
   pattern.
4. **Little Rock ladder is clamped.** Insert at L5 and shift only NYC→Berlin
   up one each; Toronto/Sydney/Tokyo stay 19/20/20 so nothing exceeds L20.
   This is a cleaner fix than the plan's literal "NYC L6" which would have
   pushed Sydney/Tokyo to 21.
5. **Analytics = one `sessionStats` row per session** (start/end/duration/
   missions/city/service), counts only, opt-in, founder-gated summary.

## Risks

- **RISK:** Little Rock's OSM relation (16795) has changed or lacks a clean
  single outer ring.
  **IMPACT:** Boundary file is wrong → missions spawn outside city limits.
  **LIKELIHOOD:** low. **MITIGATION:** verify the relation live before
  generating; fall back to the TIGER/Line place shapefile (the pipeline both
  Memphis/Nashville already used).
- **RISK:** The ladder shift (NYC→Berlin +1) re-keys saves that stored a city
  name at a now-different level.
  **IMPACT:** A commander already in NYC at L5 might appear "unlocked at L6."
  **LIKELIHOOD:** medium. **MITIGATION:** relocation is already level-gated
  at *entry*, not re-checked for the current city; confirm `relocateCity`
  doesn't re-validate the current city, and add a test.
- **RISK:** e2e needs Postgres in CI; the server boot guard refuses to start
  unpinned.
  **IMPACT:** CI fails to boot. **LIKELIHOOD:** medium. **MITIGATION:** run
  with `NODE_ENV=test` (documented bypass) + the docker-compose Postgres;
  capture the boot-guard error in the workflow.
- **RISK:** Analytics table needs `--db-push` on a live DB with real players.
  **IMPACT:** a botched push is hard to unwind. **LIKELIHOOD:** low.
  **MITIGATION:** additive table only (no column changes); run
  `database-migration` skill; follow the RELEASES.md backup step.

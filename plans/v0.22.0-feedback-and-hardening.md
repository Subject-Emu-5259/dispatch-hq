## Task 1 — Feedback bug-fix batch (from this session)

### 1a. New-update reload nudge (kills the stale-bundle complaint class)
**Status: ✅ done** — v0.22.0.

The mission popup was reported "white" — production was verified dark; the
user's browser was serving a stale cached bundle (SW v23 already network-first,
but users don't always reload). Shipped the standard PWA pattern so this never
surfaces as a "bug" again:
- **`useUpdateNudge` hook** (mounted in App.tsx): on boot and on window
  `focus` (30s throttle), fetches `/health` (public, already returns `version`
  — no new server surface) and compares it to the running bundle's version via
  a new `currentVersion()` helper in `releaseNotes.ts`.
- When the server is newer, a one-time notification fires: **"Update available
  — reload to get the latest"** (icon 🔄, names the live version, tap →
  `location.reload()`). One nudge per version per browser (localStorage
  memorialized), fully silent on failure (offline / dev server 404s).
- Pure comparison logic lives in `lib/versionCheck.ts` (numeric segment
  compare, tolerates leading `v` and malformed segments — never treats an
  empty version as newer) with 8 unit tests; the hook has 5 component tests
  (visible notification, equal-version silence, offline silence, one-time
  guard, focus throttle). Web suite 199/199.

**Touchpoints:** `apps/web/src/hooks/useUpdateNudge.ts` (new), `apps/web/src/lib/versionCheck.ts` (+test, new), `apps/web/src/components/useUpdateNudge.test.tsx` (new), `apps/web/src/App.tsx`, `apps/web/src/data/releaseNotes.ts` (`currentVersion()` helper).

## Task 2 — Economy rebalance (carried #1 from audit)
**Status: ✅ done** — v0.22.0.

`levelBonus`/`ECONOMY` constants are declared in shared but never consumed by
payout math — payouts used rank bonuses only. Shipped:
- **`computeMissionRewards` now consumes `ECONOMY.levelBonus`** (×1.0 at L1 →
  ×2.0 at L20) on **credits only** — XP keeps the rank ladder alone so
  progression doesn't self-accelerate, and the alliance-XP credit is untouched
  (it rides the XP side). The credits and XP multiplier stacks are split
  internally; the public `finalMult` is the credit multiplier (the headline
  payout) and a new `levelBonus` field joins the breakdown. Neutral at L1, so
  new players see zero change — the curve is correctness + mild progression,
  not a reset.
- **Reward-band retune:** the `REWARD_BAND_PCT` (±20%) framework from the
  v0.18 pass was already in shared (`medianRewardForDifficulty`,
  `rewardBandFor`) but never audited. The audit found **five police outliers**
  and re-tuned them into band: theft 120→105, traffic stop 60→75, school-zone
  speeding 110→100, DUI checkpoint 220→210, signal malfunction 140→155.
- **Tests:** new shared `missions.test.ts` (6 tests) pins **every template in
  all three service pools** inside its difficulty band — the audit is now a
  regression gate — plus band-helper math tests; `rewards.test.ts` gained 5
  level-bonus tests (neutral at L1, credits-only scaling at L10, cap ×2.0 at
  L20+, floor ×1.0 below L1, alliance XP unaffected) and the full-stack test
  now asserts the level curve in the compound.
- Client-authoritative caveat unchanged: server deltas stay raw (v0.19 note).

**Touchpoints:** `packages/shared/src/constants/missions.ts` (+ new `missions.test.ts`), `apps/web/src/lib/rewards.ts` (+ test). Suite: shared 100/100, web 204/204, all tsc clean, web bundle builds.

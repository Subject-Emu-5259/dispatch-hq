# v0.31.0 — Membership & Coins Monetization

> **Theme:** Land the monetization the itch.io promo already promises before the
> **Oct 27 "Buy Now"** flip. Today `PREMIUM` multipliers, `players.coins`, and
> `players.isPremium` all exist but do nothing: coins are admin/promo-granted with
> no way to spend them, premium has no storefront and its two declared multipliers
> are not consumed by reward or training math, and the date-gated widget flips to a
> "Buy Now" button that currently points at nothing. This batch builds the store,
> the checkout, the coin economy, and wires the declared multipliers into gameplay.

**Current state:** v0.30.0 live. `players` already has `coins` (int, default 0) and
`isPremium` (bool, default false). `PREMIUM = { monthlyPrice: 999, creditMultiplier: 2,
trainingSpeedMultiplier: 2 }` lives in `packages/shared/src/constants/economy.ts` and is
referenced by **zero** runtime code. Promo codes and the admin "grant bonus" path already
award coins/credits/xp/level (the fulfillment machinery exists). **No schema change has
touched payments before** — this is the first `--db-push` release since v0.24.

---

## What already exists (do NOT re-implement)

- **Coin/credits/xp/level grants** — `routes/admin.ts` `applyRewards` + `routes/promos.ts`
  already credit `players.coins`, and the client applies them through the live-sync delta
  (`App.tsx` `coinGrant`). The storefront's *fulfillment* half is 90% built.
- **`players.isPremium`** — returned by `sanitizePlayer` (auth) and carried through the
  save/identity sync. The flag is plumbed; only the *gate* (buy → activate → expire) and
  the *multipliers* are missing.
- **Admin Console** — has a Promo Codes tab and a Bonus tab; the natural home for an
  Orders/Revenue tab using the same patterns.
- **Date-gated promo** — `itchPromoLabel()` already flips to "Buy Now" on Oct 27; it just
  needs a real target URL (the new shop route) instead of the plain itch page.

## Pricing (locked in this plan)

### Membership — one tier at launch

| Tier | Price | Benefits |
|---|---|---|
| **Commander** | **$9.99/mo** (999¢, matches `PREMIUM.monthlyPrice`) | ×2 credits on every call · ×2 training speed · ✦ badge in TopBar + profile · members-only inbox note |

### Coin packs (premium currency ladder)

| Pack | Price | Coins | Bonus |
|---|---|---|---|
| Starter | $0.99 | 100 | — |
| Bucket | $4.99 | 550 | +10% |
| Chest | $9.99 | 1,200 | +20% |
| Vault | $19.99 | 2,600 | +30% |
| Bank | $49.99 | 7,500 | +50% |

Anchor: **100 coins ≈ $1.00**.

### Coin sinks (what coins buy — the economy needs an exit or it's just a donation)

1. **Skip unit training** — `ceil(remainingSeconds / 10)` coins (min 1), so a 2-minute
   wait is ~12 coins. Reuses the existing `trainingEndsAt` timestamp.
2. **Buy credits** — 100 coins → 5,000 credits ($1 ≈ 5,000 cr). Converted server-side
   through the same `applyRewards`-style credit path.

## Schema (new tables + one column)

All new tables mirror the existing drizzle style (uuid PKs, `created_at` with tz, indexed FKs).

```ts
// Catalog of membership tiers (one row at launch; table is future-proofing).
export const membershipTiers = pgTable('membership_tiers', {
  id: uuid('id').primaryKey().defaultRandom(),
  key: varchar('key', { length: 40 }).unique().notNull(),          // 'commander'
  name: varchar('name', { length: 60 }).notNull(),
  priceCents: integer('price_cents').notNull(),                     // 999
  creditMultiplier: real('credit_multiplier').default(1).notNull(), // 2.0
  trainingSpeedMultiplier: real('training_speed_multiplier').default(1).notNull(), // 2.0
  perks: jsonb('perks').default([]).notNull(),                      // ['badge','inbox']
  active: boolean('active').default(true).notNull(),
});

// Catalog of coin packs (5 rows, seeded at boot like achievements).
export const coinPacks = pgTable('coin_packs', {
  id: uuid('id').primaryKey().defaultRandom(),
  key: varchar('key', { length: 40 }).unique().notNull(),          // 'starter'|'bucket'|...
  name: varchar('name', { length: 60 }).notNull(),
  priceCents: integer('price_cents').notNull(),
  coinCount: integer('coin_count').notNull(),
  sortOrder: integer('sort_order').default(0).notNull(),
  active: boolean('active').default(true).notNull(),
});

// Purchase ledger — every membership order and coin-pack order.
export const orders = pgTable('orders', {
  id: uuid('id').primaryKey().defaultRandom(),
  playerId: uuid('player_id').references(() => players.id).notNull(),
  kind: varchar('kind', { length: 20 }).notNull(),          // 'membership' | 'coin_pack'
  itemId: uuid('item_id').notNull(),                        // tier id or pack id
  priceCents: integer('price_cents').notNull(),
  status: varchar('status', { length: 20 }).default('pending').notNull(), // pending|paid|fulfilled|refunded|failed
  provider: varchar('provider', { length: 20 }).default('stripe').notNull(),
  providerRef: varchar('provider_ref', { length: 120 }),     // Stripe session/sub id
  createdAt: timestamp('created_at', { withTimezone: true }).defaultNow().notNull(),
  paidAt: timestamp('paid_at', { withTimezone: true }),
  fulfilledAt: timestamp('fulfilled_at', { withTimezone: true }),
}, (t) => [index('idx_orders_player').on(t.playerId), index('idx_orders_status').on(t.status)]);

// Coin transaction ledger — every delta (purchase, spend, promo, admin, refund)
// so the coin economy is auditable end-to-end (never just mutate players.coins).
export const coinTransactions = pgTable('coin_transactions', {
  id: uuid('id').primaryKey().defaultRandom(),
  playerId: uuid('player_id').references(() => players.id).notNull(),
  delta: integer('delta').notNull(),                        // +100 purchase, -12 spend
  reason: varchar('reason', { length: 20 }).notNull(),      // purchase|spend|promo|admin|refund
  refId: uuid('ref_id'),                                    // order id / promo id / etc
  balanceAfter: integer('balance_after').notNull(),
  createdAt: timestamp('created_at', { withTimezone: true }).defaultNow().notNull(),
}, (t) => [index('idx_coin_tx_player').on(t.playerId), index('idx_coin_tx_time').on(t.createdAt)]);

// players gains one column (drizzle push handles it — no destructive migration):
//   premiumExpiresAt: timestamp('premium_expires_at', { withTimezone: true }),
// isPremium stays the fast boolean, recomputed from premiumExpiresAt on read;
// premiumExpiresAt drives renewal/expiry (a daily sweep flips the flag off).
```

`isPremium` semantics: **active = `premiumExpiresAt > now()`**. The boolean column stays
(kept in sync) so the existing `sanitizePlayer`/save/auth reads don't churn; a scheduled
sweep (piggyback on the existing guest-prune daily job) flips `isPremium=false` when the
window lapses. No entitlement table needed for one tier — `premiumExpiresAt` **is** the
entitlement.

## Tasks

### 1. Catalog + schema + seed

**Files:** `servers/game-server/src/db/schema.ts` (4 tables + `players.premiumExpiresAt`),
new `servers/game-server/src/lib/shop.ts` (pure catalog helpers: `coinPackByKey`,
`membershipTierByKey`, `premiumActive(player)`, `premiumMultipliers(player)`),
new `servers/game-server/src/db/seed.ts` or extend `ensureAchievements`-style seeding,
`servers/game-server/src/__tests__/shop.test.ts`

- **1.1** Add the four tables + the `premiumExpiresAt` column to `schema.ts` (drizzle push,
  no destructive change — additive only).
- **1.2** Seed `membership_tiers` (one `commander` row, 999¢, ×2/×2) and `coin_packs`
  (five rows, the ladder above) at boot, idempotent like `ensureAchievements`.
- **1.3** `lib/shop.ts` pure helpers: `premiumActive(player)` → `premiumExpiresAt > now`;
  `premiumMultipliers(player)` → `{ credit: 2, training: 2 }` when active else `{1,1}`.
- **1.4** Tests: seed idempotency (two boots → still 1 tier + 5 packs), `premiumActive`
  true/false/expired, multipliers fall back to 1 for non-members.

**AC:** boot seeds the catalog; `/api/shop/catalog` (task 4) has data to read.

**Feasibility:** High. Additive drizzle + a pure helper module + seed — the `achievements`
pattern. The only new ground is the first `--db-push` since v0.24 (runbook §2 covers it).

### 2. Checkout + webhook + fulfillment

**Files:** new `servers/game-server/src/routes/shop.ts`, `config.ts` (Stripe env + provider
switch), `servers/game-server/src/lib/stripe.ts` (client + webhook verify),
`__tests__/shopCheckout.test.ts`

- **2.1** `POST /api/shop/checkout` (auth) — body `{ kind, itemId }`; validates the item,
  writes a `pending` `orders` row, creates a Stripe Checkout Session (one-time price for a
  pack, subscription price for the tier) with `client_reference_id = playerId` +
  `metadata.orderId`, returns `{ url }`.
- **2.2** `POST /api/shop/webhook` (unauthenticated, signature-verified) — handles:
  - `checkout.session.completed` → mark order `paid`, grant coins (pack) or set
    `premiumExpiresAt = now + 30d` + `isPremium = true` (tier), write the `coin_transactions`
    row, mark `fulfilled`. **Idempotent** (order status guard — a duplicate webhook must not
    double-grant).
  - `customer.subscription.deleted` / `invoice.payment_failed` → clear `premiumExpiresAt`,
    flip `isPremium=false`.
- **2.3** **Manual-provider fallback** — `PAYMENT_PROVIDER=manual` (default when
  `STRIPE_SECRET_KEY` is unset): checkout returns a "purchase off-platform, then redeem
  this code" flow. The founder grants via the existing admin bonus path and the player's
  coin balance updates through the live-sync delta. This is the **Oct 27 unblock** — the
  store ships and can transact the moment Stripe keys land, but nothing is hard-wired to
  Stripe.
- **2.4** Config + boot guard: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRICE_*`
  optional env; when set, checkout is live. Warn loudly (not a hard stop) when a paid
  catalog exists but no keys, mirroring the Redis warning pattern.

**AC:** a paid webhook grants exactly once; a duplicate is a no-op; membership sets
`premiumExpiresAt`; manual mode degrades gracefully.

**Feasibility:** Medium-High. The webhook/idempotency contract is the one real trap
(double-grant on retry) — mitigated by the order-status guard + a unique webhook-event
idempotency key. Stripe account creation is the **external dependency** (owner action,
flagged in Risks).

### 3. Wire the premium multipliers + coin sinks

**Files:** `apps/web/src/lib/rewards.ts` (credit multiplier), `apps/web/src/lib/training.ts`
(training speed), `servers/game-server/src/routes/shop.ts` (spend endpoints),
`apps/web/src/lib/apiClient.ts` (typed fetches), `apps/web/src/components/ShopModal.tsx` (new)

- **3.1** **Premium ×2 credits** — `computeMissionRewards` accepts an optional
  `premiumMultiplier` (default 1) and folds it into `creditMult` (the declared
  `PREMIUM.creditMultiplier` finally reaches payout math). The call site passes
  `premiumMultipliers(player).credit`.
- **3.2** **Premium ×2 training** — `unitTrainDurationSec(level)` is divided by
  `premiumMultipliers(player).training` at call time (cap the floor so a member's training
  can't hit 0).
- **3.3** **Coin sinks (server-authoritative)** — `POST /api/shop/spend` body
  `{ kind: 'skip_training', unitId }` or `{ kind: 'buy_credits', amount }`; validates the
  balance, debits `players.coins` **and** writes the `coin_transactions` row in one
  transaction, returns the new balances. `skip_training` clears `trainingEndsAt`; the
  per-second cost is the pure `skipTrainingCost(remainingSec)` helper (tested).
- **3.4** Tests: `computeMissionRewards` ×2 with premium, training duration halved,
  `skipTrainingCost` boundary (0s → min 1), spend rejection on insufficient coins, and the
  ledger row lands atomically with the debit.

**AC:** a member earns ×2 credits and trains ×2 fast; a coin spend debits the balance and
leaves an auditable `coin_transactions` row.

**Feasibility:** High. Two multiplier insertion points + one transactional endpoint. The
rewards/training paths are pure and already unit-tested — extend, don't rewrite.

## Risks / notes

- **Stripe account + keys are an external dependency** (owner action: create the account,
  add `STRIPE_SECRET_KEY`/`STRIPE_WEBHOOK_SECRET`/price IDs to the Zo service env). The
  `PAYMENT_PROVIDER=manual` fallback means the store can ship and the "Buy Now" flip is
  never a dead end even if keys land after Oct 27.
- **Webhook double-grant is the one correctness trap** — every grant is guarded by the order
  `status` transition (`pending → paid → fulfilled`) plus an idempotency key on the event id.
- **Coins need a real sink or they're donations.** `skip_training` + `buy_credits` are the
  MVP exits; both are pay-to-accelerate (never pay-to-win: credits/units remain earnable
  in-game at the same rates).
- **First `--db-push` since v0.24** — run it against the instance exactly per runbook §2
  (backup first); the tables are additive so rollback is non-destructive.
- **Premium expiry sweep** must exist or a lapsed member keeps ×2 forever — piggyback the
  daily guest-prune job.

# v0.21.0 — "The Big One": Cities, Seasons & Scale

The full queued backlog from the release-readiness audit: performance, deploy
hardening, the multi-city campaign arc, seasonal events, and the personnel arc.
Deployed 2026-08-12.

## 1. Deploy hardening (scripts/deploy.sh + plans/RELEASES.md)
- Added a **retry-until-real-response gate** to the `--run` path: the deploy
  API call now loops (default 8 attempts) until a non-empty JSON response
  arrives, logging every swallowed attempt. Kills the v0.20.5 303-redirect
  double-deploy bug class.
- Runbook updated with the lesson ("expect one real response before considering
  the deploy submitted").

## 2. Performance (apps/web/src/components/map/MapView.tsx)
- **Mission-marker clustering**: below `CLUSTER_ZOOM` (13), pins within
  `CLUSTER_PX` (60 px screen distance) merge into count pills with the most
  urgent category icon. Cluster keys derive from sorted member ids → stable
  tick-to-tick (position-only updates, no flicker). Clicking a pill eases the
  map in to split it; the selected mission is always rendered solo. A `zoomend`
  listener bumps a `zoomBump` state so clusters re-compute on zoom.
- **Route-line coalescing**: replaced per-unit sources/layers (`route-<id>-traveled/-remain`,
  5 layers each) with two shared sources (`route-traveled`, `route-remain`) and
  exactly 5 layers total, fed by a FeatureCollection rebuilt each tick. Uniform
  paint means nothing is lost; patrol GPS runs the same pipeline.
- **Dispatch Board**: already paginated (24 + "Show more") — noted in the plan,
  no windowing lib added (would be churn).

## 3. Multi-city campaign (Memphis + relocation)
- `apps/web/src/data/memphisBoundary.ts`: real Memphis, TN city-limits polygon
  (OSM relation 197239, 75-point outer ring + 3 holes), registered in
  `cityBoundaries.ts` and added to the popular-city list with precise bounds.
- `apps/web/src/lib/cityProgression.ts`: `CITY_ACCESS` level gates
  (West Memphis L1 → Memphis L3 → NYC L5 → … → Tokyo L20) + helpers.
- `gameStore.relocateCity()`: re-settles stations/units inside the new city's
  bounds, clears missions/patrols, reseeds criminal records; career/economy/
  settings/crew carry over.
- `CitySelectionScreen` gains `mode: 'new' | 'relocate'`: lock badges + unlock
  hints in the picker, guarded `handleCitySelect`, and a relocate confirm that
  skips the fresh-campaign reset. `PauseScreen` gains a **Relocate Command**
  button (saves first, then opens the picker).

## 4. Seasonal events (apps/web/src/lib/seasonal.ts)
- Date-window engine: `SEASONAL_EVENTS` (Fourth of July Jul 1–6, Christmas
  Dec 24–26) → banner notification on session start + hourly re-check.
- Boosted callouts: `seasonalBoostedPick` in `spawn.ts` (35% of boosted types
  roll during the window). Reward multiplier 1.5× wired through
  `computeMissionRewards.seasonalMult`. Badge awarded once per session on any
  completion during the window via the idempotent server endpoint
  (`seasonal_4th_of_july`, `seasonal_christmas`).

## 5. Personnel arc
- **Readiness-aware dispatch AI** (`AIDispatch.tsx`): for difficulty ≥ 7 calls
  the assistant ranks candidates by crew effectiveness (via `crewReadiness`)
  before distance; routine calls stay distance-first. No-op with Shift Pressure
  off.
- **Trait re-roll** (`EmployeesPanel.tsx` + `employees.rerollTraits`): 300
  credits per crew member re-rolls their traits, gated on funds and roster.

## v0.21.1 follow-ups (same umbrella release)
- **Nashville, TN** — third precise-boundary launch city (OSM relation 197472, 70-pt ring + 2 holes), unlocked at Level 4. Registry: `data/nashvilleBoundary.ts` + `cityBoundaries.ts` + picker + `CITY_ACCESS`.
- **Relocation cost + briefing** — `relocateCost(stations, units)` (5,000 base + 2,000/station + 1,500/unit) enforced on confirm; a third picker step summarizes what carries over vs. resets before committing.
- **Coverage-gap overlay** — `lib/coverage.ts` (pure, tested) shades zones beyond every station's effective radius: red full gap, amber partial; new top-bar toggle.
- **Seasonal leaderboard contest** — server-tracked clears per holiday window (`seasonal_contest_entries` + `seasonal_contests` tables), live standings in the Leaderboard → Seasonal tab, and the top clearer wins the winner badge (lazy, idempotent resolution when the window closes). Also fixed the v0.21.0 bug where seasonal badges 404'd because the achievements were never seeded server-side.

**Deploy note:** this release adds DB tables → `scripts/deploy.sh --db-push` required.

## Tradeoffs
- Only two cities carry *precise* boundaries (West Memphis, Memphis); the other
  popular cities keep bbox-based spawn clamping. The pipeline is documented —
  adding a city is data + a one-line registry entry.
- Dispatch Board "virtualization" is pagination, not windowing — at 24 cards
  per page with lightweight rows this is the right tradeoff.
- Seasonal badges are server-created on first award (dynamic achievements);
  there's no retroactive badge for completing calls before this release.

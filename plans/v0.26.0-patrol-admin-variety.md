# v0.26.0 — Patrol Depth, Two New Calls & A Smarter Admin Console

> **Theme:** Make patrol behavior actually read the city it is in, keep the
> mission pools growing, and round out the founder console with export + drill
> affordances. Small, low-risk batch — no schema changes, no new systems.

**Current state:** v0.25.0 live (auth hardening, five new calls, keyboard
polish). This release continues the polish + variety cadence: one server
hardening item, one gameplay-depth item, one content item, and two admin-UI
items.

---

## Tasks

### 1. Per-player autosave throttle (server)

**Files:** `servers/game-server/src/lib/rateLimit.ts`,
`servers/game-server/src/lib/rateLimit.test.ts`,
`servers/game-server/src/routes/saves.ts`

`POST /api/player/saves` was the only high-frequency authenticated write with
no throttle — a buggy client or a scripted token could hammer the jsonb upsert
unbounded. The rate limiter now accepts an optional `keyFn` (defaults to client
IP), and saves throttle per-account (`player:<id>`, 30/min) so several players
behind one NAT don't share a bucket. One new unit test proves the custom-key
behavior.

### 2. Patrol reads the city (gameplay depth)

**Files:** `apps/web/src/lib/patrol/patrolEngine.ts`,
`apps/web/src/lib/patrol/patrolEngine.test.ts` (new)

`suggestPatrolMode` had a dead `return 'zone'` fallthrough: it could never
suggest `station-beat`, so quiet/small cities always got a full-city zone loop
that looked wrong. It now returns `station-beat` when the city is quiet and
small — a unit stays close to its station when nothing is happening, while
busy metros still `hotspot` and big footprints still `city-sweep`. Added the
first patrol-engine unit tests (6 cases): mode selection across all four
branches, a route for every mode, and station-beat looping back near the
station. Route planning is tested with `fetchDrivingRoute` mocked so it never
hits OSRM.

### 3. Two new mission templates (content variety)

**Files:** `packages/shared/src/constants/missions.ts`,
`packages/shared/src/constants/constants.test.ts`

| Template | Category | Difficulty | Credits |
|---|---|---|---|
| Brush Fire | fire | 4 | 425 |
| Water Rescue | ems | 5 | 425 |

Both are inserted at their tier's current median credit value, so the ±20%
reward bands are unchanged and every existing template stays in-band
(`missions.test.ts` green). Counts: fire 16→17, ems 17→18, police unchanged.

### 4. Admin console CSV export (UI)

**Files:** `apps/web/src/components/AdminPanel.tsx`

The "Last 7 Days" block gains a one-click **CSV** download of the summary
(sessions / avg duration / missions cleared / avg response) plus the full
per-type breakdown (count, avg, p50/p90/p99). RFC-4180 quoting via a small
`buildAnalyticsCsv` helper; client-side Blob download, no server round-trip.

### 5. Per-type show-all + empty state (UI)

**Files:** `apps/web/src/components/AdminPanel.tsx`

The per-type list was hard-capped at 6 rows with no indication more existed.
It now shows 6 by default with a "Show all N types" toggle, and shows a proper
empty state ("No mission activity recorded yet") instead of rendering nothing
when `missionsByType` is empty.

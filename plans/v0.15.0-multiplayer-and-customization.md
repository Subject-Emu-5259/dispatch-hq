# v0.15.0 — Multiplayer & Customization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Make the shared city feel alive — streaming unit movement between players — and give commanders identity through alliances, unit liveries, and station themes.

**Architecture:** Unit movement becomes a relay: clients send throttled `unit_position` WebSocket messages (with speed-cap validation server-side), the server fan-outs to players whose viewport contains the unit, and `MapView` interpolates remote units along their last two positions. Alliances add two Drizzle tables, a REST route group, WS presence tags, and a Sidebar section with shared-map visibility. Liveries/themes are data-driven (shared constants + per-unit/station persisted fields) rendered on markers and cards.

**Tech Stack:** TypeScript, Hono + Drizzle + Postgres, WebSocket (`wsServer.ts`/`connectionManager.ts`), MapLibre GL, Zustand, Tailwind CSS.

## Global Constraints

- WS protocol types live in `packages/shared/src/types/events.ts` (client ↔ server message union).
- Existing messages: `viewport_update` → `nearby_state`, `presence` broadcast every 10s (`wsServer.ts`).
- DB via Drizzle (`servers/game-server/src/db/schema.ts`), migrations applied on Zo.
- UI: dark-first Tailwind, lucide-react.
- Validation: web + server typechecks, `pnpm build`, server vitest, shared vitest.

  ```ts
  export const MAX_SPEED_KMH = 60;
  export const SPEED_TOLERANCE = 1.4;   // legit moves pass, teleports fail
  export const THROTTLE_MS = 500;
  export function haversineKm(a: { lat: number; lng: number }, b: { lat: number; lng: number }): number;
  export function unitSpeedOk(prev: { lat: number; lng: number; at: number }, next: { lat: number; lng: number; at: number }): boolean;
  export function withinThrottle(lastAt: number | undefined, now: number): boolean;
  export function viewportContains(v: { lat: number; lng: number; radiusKm: number }, p: { lat: number; lng: number }): boolean;
  // connectionManager.ts
  relayUnitPosition(sender: string, msg: UnitPositionMessage, playerId: string, now: number): UnitPositionBroadcast[];
  // thin wrapper: throttle + unitSpeedOk + viewportContains over unitPositions/viewport maps;
  // returns broadcasts for each *other* connected player whose viewport contains (lat,lng).
  ```

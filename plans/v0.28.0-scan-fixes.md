## Tasks

### 1. Clamp unit speed readouts to the rated max (UI fix — scan finding 1)

**Files:** `apps/web/src/lib/techTree.ts`, `SelectedUnitPanel.tsx`,
`UnitPanel.tsx`

The unit HUD showed `Speed 52 mph` next to `max 51 mph`. En-route movement is
ETA-based and its derived speed can momentarily overshoot the raw spec, and
the display code never clamped against `getUnitMaxSpeedMph`. Added
`getUnitCurrentSpeedMph(unit)` — same display semantics as before (idle units
quote their spec, everything else quotes `currentSpeed`), but clamped to the
unit's effective max — and used it in both the selected-unit panel and the
fleet card. The `max N mph` line stays as-is, so the two numbers can never
contradict again.

### 2. Stress meter transparency (UI fix — scan finding 2)

**Files:** `apps/web/src/components/StressMeter.tsx`

At 100% stress the meter gave no signal of what that state means or how
recovery works. The meter is advisory (no hidden penalty), so the fix makes
the advisory explicit rather than inventing mechanics:
- **Consequence line** per severity in the tooltip ("Overextended — clear
  calls, recall units, and let recovery bring stress down…"), highlighted at
  High/Critical.
- **Recovery math** — the exact per-tick model: `+2` active mission, `+15`
  failed mission, `−3` per available unit, `−1` natural decay.
- **Critical indicator** — a pulsing ⚠ next to the percentage at ≥80 so the
  state is glanceable on the dock itself, not only inside the tooltip.

### 3. Incoming-911 variety guard (game fix — scan finding 3)

**Files:** `apps/web/src/components/UnifiedDispatchCenter.tsx`

The scan caught two `Multi-Vehicle Crash` (HIGH) calls ringing at once. The
organic mission spawn loop already has a variety guard (`avoidRecentTemplate`),
but the CAD's `generateRandomCall` picked uniformly from `INCIDENT_TEMPLATES`
with no memory. Added a per-service rolling window of recently rung
`reportedType`s: a repeat roll re-picks from the rest of the pool, falling
back to the original pick when the pool is too small to avoid starvation
(4-template police board, window 4). Same mechanism, one small function.

### 4. Dev-proxy hardening (dev fix — scan findings 4–6)

**Files:** `apps/web/vite.config.ts`

In dev, `/tiles/*` 500'd, `/routing/*` 500'd (straight-line fallback), and the
WS chip showed "Offline". Production was fine because the server's
`mapData.ts` proxy sends a real `User-Agent` — OSM and the public OSRM demo
reject http-proxy's default UA. The Vite proxies now mirror the server's
header set: `changeOrigin: true` + the same UA/`Accept` headers on `/tiles`,
`/routing`, and `/geocode`. (The WS handshake failure is the Vite proxy being
unable to tunnel the upgrade to the remote host — production serves WS
directly and is unaffected; noted in the scan, not fixable from a dev proxy
config without a local server.)

### 5. Static-file resolver regression tests (server hardening)

**Files:** `servers/game-server/src/lib/staticFiles.ts` (new) +
`staticFiles.test.ts` (new, 9 cases), `serve-combined.ts`

The two v0.27 hotfixes both shipped because the static-file rules were inline
and untested: the homepage EISDIR 500 (root "/" resolved to a directory and
`readFileSync` threw) and the font/icon MIME fallback (served as `text/html`
from the SPA catch-all). Extracted `resolveStaticFile(frontendDir, reqPath)`
— a pure, synchronous resolver covering traversal, existence, and
directory-rejection — and wired `serveStatic` through it. Tests pin the root
directory case, `/fonts/fonts.css` → `text/css`, `/icon-192.png` →
`image/png`, hashed assets, traversal (`/../`, `/assets/../../etc/passwd`),
missing files, and unknown-extension fallback.

## What already exists (do NOT re-implement)

### LA slice
- **LA is fully wired as a launch city** — boundary polygon with six carved
  enclave holes (`losAngelesBoundary.ts`), registered in
  `NORMALIZED_BOUNDARIES`, LAC+USC trauma referral (`hospital.ts`), prewarm
  bbox (`scripts/prewarm-map.sh`), L8 unlock (`cityProgression.ts`), picker
  card, station-spot config. Missions already spawn inside the real limits.
- **What LA lacks vs. the other cities:** zero city-specific street / landmark
  / zone-name data. `apps/web/src/data/cityStreets.ts` is **West Memphis-only**
  (`CITY_NAME = 'West Memphis'`), and its four helpers
  (`streetsForZone`, `landmarksForZone`, `zoneNameForId`, `crossStreetsForZone`)
  take only a zone id — no city argument. Every consumer
  (`radioDialogueEngine.ts`, `UnifiedDispatchCenter.tsx`, `fieldActivities.ts`)
  therefore quotes Broadway Ave / the I-40 interchange / "Downtown" in LA.
- **The city context plumbing already exists:** `setRadioCityContext(zones,
  cityName, pois)` is called from `gameStore.ts` (4 call sites: city select /
  load / relocate) and `RadioComms.tsx`, and the engine already falls back to
  generic pools when unset. The street data just needs the same treatment.

### e2e expansion
- **Smoke covers:** guest → new campaign → build station → buy patrol car →
  START PATROL → save → reload → resume (patrol verified) → dispatch → `en
  route` (`apps/web/e2e/smoke.mjs`, police service, West Memphis only).
- **Still integration-only per the audit:** mission **completion** (on_scene →
  returning → credits), **fire/EMS** services (no station/unit/call of either),
  and a **second city** (the v0.32.0 LA boundary has never been exercised in a
  live browser loop). Signup gate has its own script (`e2e:signup-gate`).
- `gameSpeed` (default 1) is a persisted setting — usable to accelerate unit
  travel so a completion leg fits inside a step timeout.

  `twitter:image` point at **`logo-512.png`** (a 512×512 app logo, not a social

## Tasks

### 1. LA city slice — city-aware streets/landmarks/zone names

**Files:** `apps/web/src/data/cityStreets.ts` (refactor + new data),
new `apps/web/src/data/cityStreets.losAngeles.ts`, `apps/web/src/lib/radioDialogueEngine.ts`,
`apps/web/src/components/UnifiedDispatchCenter.tsx`, `apps/web/src/lib/fieldActivities.ts`,
new `apps/web/src/data/cityStreets.test.ts`, `apps/web/src/lib/radioDialogueEngine.test.ts` (extend)

- **1.1** Make the street registry **city-keyed**: keep the current West Memphis
  pools as the **default/fallback** (so Memphis/Nashville/LR/NYC behavior is
  byte-identical until they get their own data), and add a module-level
  `cityStreetsContext` (city name slug) set alongside `setRadioCityContext`
  (same call sites in `gameStore.ts`/`RadioComms.tsx`) or via an explicit
  `setCityStreetsContext(cityName)` invoked from the existing context setter.
- **1.2** New `cityStreets.losAngeles.ts`: real LA street pools per 3×3 zone
  (Wilshire, Sunset, Hollywood, Figueroa, Vermont, Crenshaw, Sepulveda, the
  101/110/405/10/5 freeways, La Brea…), landmarks (LAX, Griffith Observatory,
  Dodger Stadium, Union Station, the Coliseum, USC, Santa Monica Pier, the
  harbor…), and **zone names mapped to real LA districts** (Hollywood,
  Downtown, the Westside, the Valley, South LA, East LA…). **Rule:** never
  name a carved-out enclave jurisdiction (Beverly Hills, West Hollywood,
  Culver City, San Fernando, etc.) as a location — those are holes in the
  boundary and must not read as addressable places.
- **1.3** Thread the city through the four helpers (add an optional `cityName`
  param defaulting to the context, so existing callers compile unchanged) and
  through `crossStreetsText`/`makeCtx` in the radio engine.
- **1.4** Tests — LA context returns Wilshire/etc. and LA district names,
  never enclave names; missing-city context falls back to the West Memphis
  pools; `zoneNameForId` unchanged for the default.

**AC:** In an LA campaign, dispatch chatter, board cards, and field-activity
lines reference real LA streets/landmarks/districts; every other city is
bit-identical to v0.32.0.

**Feasibility:** High. Pure data + one context variable + optional params; the
consumers already go through exactly four helpers. The only care needed is the
enclave rule (assert in a test).

## Risks / notes

- **e2e timing is the one real risk** (Task 2): mission completion depends on
  travel time. Mitigations: bump `gameSpeed` in the test, reuse the smoke's
  retry scaffolding, and fall back to asserting the clear-state transition if
  the reward assertion proves flaky. Keep each new script skippable/isolated so
  one flake doesn't take down the other legs.
- **Enclave rule (Task 1):** LA's boundary carves out six neighboring cities —
  the street/landmark pools must never emit those as locations. Enforced by a
  test that greps the pools for the enclave names.
- **Belt-bounty daily limit:** only one submission per day — the three
  candidates 08–10 land across the following days; the doc sync + queue state
  is what this release owns.
- **No `--db-push`** — nothing in this batch touches `schema.ts`.

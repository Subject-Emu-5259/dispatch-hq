# v0.18.0 — Release Readiness: Depth, Scale & Hardening

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the v0.17.9 feature-complete beta into a release-ready v1.0 candidate. The original v1.0 roadmap (v0.13.1 → v0.15.0) is fully shipped; what stands between the game and a late-October public release is not more features but **progression depth** (the game currently ends at Level 10 with two dead-end units), **content parity** (EMS is the thinnest service), **scale** (live multiplayer + a busy board must stay smooth), **hardening** (CORS, rate limiting), **accessibility**, and **documentation truth** (audits and plan checkboxes lag the shipped reality).

**Architecture:** Pure shared-constants work for progression + new mission templates (T1–T2), MapLibre GeoJSON clustering + render throttling for scale (T3), CSS/ARIA/focus passes (T4), config-driven CORS + a tiny rate-limiter middleware (T5), and a docs/test-suite sweep (T6). No economy overhaul, no schema change to existing tables unless noted.

**Tech Stack:** TypeScript, Zustand, MapLibre GL, Tailwind CSS, framer-motion, Hono, vitest, drizzle.

## Global Constraints

- Mission construction goes through `apps/web/src/lib/spawn.ts` `buildMission()` — new templates are shared-constants data, never ad-hoc objects.
- New mission templates live in `packages/shared/src/constants/missions.ts` with `spawnWeight` (rarity) + `requirements`; every new template must be tested in `missions.test.ts` (difficulty tiers, service filtering).
- Progression constants live in `packages/shared/src/constants/economy.ts` — extend `xpPerLevel` + `levelBonus` in lockstep; every level must have a bonus entry (index parity, verified by a test).
- City geometry/POI tags come from the existing zone grid — new templates reference existing `tags` (`residential`, `commercial`, `industrial`, `road`, `public`).
- UI: Tailwind dark-first, lucide-react icons, framer-motion (gate heavy animations behind `prefers-reduced-motion` in T4).
- Server: Hono middleware order matters (auth before routes — see runbook lesson §6).
- Validation every task: `pnpm --filter @dispatch-hq/web exec tsc --noEmit`, `pnpm --filter @dispatch-hq/game-server exec tsc --noEmit`, targeted `vitest run`, `pnpm build`. Final release: bump version in `serve-combined.ts` + `index.ts`, add `RELEASE_NOTES` entry, deploy `scripts/deploy.sh 0.18.0 <files>`.

### Task 5: Security & hardening

**Problem:** `serve-combined.ts` CORS reflects any origin (`origin: (origin) => origin || '*'` with `credentials: true`); there is no HTTP rate limiting on auth, promo redemption, or bug reports (only WS unit-position throttling exists).

**Files:**
- Modify: `servers/game-server/src/serve-combined.ts`
- Modify: `servers/game-server/src/config.ts` (corsOrigin list)
- New: `servers/game-server/src/lib/rateLimit.ts` (+ unit test)
- Modify: `servers/game-server/src/routes/auth.ts`, `routes/promos.ts`, `routes/bugReports.ts`

**Step 1: CORS allowlist** — add `corsOrigins: string[]` to config (default: the Zo public URL + `localhost:3000` for dev); `cors({ origin: (o) => config.corsOrigins.includes(o) ? o : config.corsOrigins[0], credentials: true })`. Test: a disallowed origin gets no `Access-Control-Allow-Origin` header.

**Step 2: Rate-limiter middleware** — a small in-memory token bucket (`lib/rateLimit.ts`): `limit({ windowMs, max })` returning a Hono middleware; on breach, `429` with `Retry-After`. Mount on: `POST /api/auth/login`, `/api/auth/register`, `/api/promos/redeem`, `POST /api/bug-reports` (e.g. 10/min per IP), and `POST /api/chat` (20/min, mirrors the WS chat throttle). Unit tests: burst → blocked, window reset, IP isolation.

**Step 3: Input bounds** — cap bug-report description (2 000 chars) and chat message length (500 chars) server-side if not already bounded; enforce on the client too.

**Step 4: Typecheck + tests + build + commit** (`feat(server): CORS allowlist + rate limiting`).
